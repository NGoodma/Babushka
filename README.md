# Babushka bot

Статус на 2026-11-06: бот работает на Cloudflare Workers (`https://babushka.nikkidriwe57.workers.dev`), код в публичном репозитории `NGoodma/Babushka`, каждый push в `main` выкладывает его автоматически.

## Зачем

Ботом пользуется внук или внучка, которым трудно поддерживать связь с бабушкой на расстоянии. Каждый день бот присылает готовое сообщение:

> Бабуль, привет! С праздником иконы Всех скорбящих радость! Как жизнь молодая?

Под сообщением две кнопки:
- **📋 Скопировать**: Telegram копирует текст в буфер обмена (кнопка `copy_text`, текст до 256 символов, тест это проверяет);
- **⚙️ Настройки**: кнопки этого же сообщения меняются на меню:
  - **Как часто**: каждый день, раз в 2…6 дней, раз в неделю;
  - **Вопросы**: список из 14 вопросов с галочками; нажатие выключает или включает вопрос. Хотя бы один вопрос остаётся включённым;
  - **Часовой пояс**: 25 городов, у каждого показано текущее время, пользователь выбирает строку, где время совпадает с его часами. По умолчанию Москва. Сам слот (10:00–10:55) пользователь не выбирает и не видит в настройках;
  - **← Назад**: возвращает кнопки «Скопировать» и «Настройки».

Команда одна, `/start`. Любое другое сообщение от подписчика бот считает просьбой и присылает ещё одну фразу. Расписание от этого не сдвигается.

## Время отправки

- Пользователи распределяются по 12 слотам: 10:00, 10:05, …, 10:55 **по местному времени пользователя** (поле `tz`, часовой пояс IANA). Новый пользователь попадает в самый свободный слот, а при равенстве в самый ранний. Получается так: 1-й в 10:00, 2-й в 10:05, …, 12-й в 10:55, 13-й снова в 10:00. Если кто-то отписался, его место займёт следующий новый пользователь.
- Telegram не сообщает боту часовой пояс, поэтому пользователь выбирает его в настройках. Переход на летнее время учитывается (используется `Intl` с поясами IANA).
- Cron запускается каждые 5 минут круглые сутки (`*/5 * * * *`), потому что у пользователей разные часовые пояса. Каждый запуск берёт тех, у кого по их местному времени слот уже наступил и с `last_sent` (местная дата) прошло не меньше `every` дней. Если запуск пропал, следующий подберёт пропущенных. Праздник выбирается по местной дате пользователя.
- Cron сам ничего не отправляет. Он ставит пользователям `last_sent` (одним SQL-запросом через `json_each`, у каждого своя местная дата) и кладёт сообщения в очередь. Очередь отправляет пачками по 40, потому что на бесплатном тарифе один запуск может сделать не больше 50 внешних запросов.
- Если пользователь заблокировал бота (Telegram отвечает 403), он удаляется из базы. При ошибке 429 (слишком много запросов) очередь повторяет отправку после паузы, при других ошибках делает до 3 повторов.

## Как устроен код

```
src/
  index.js      # вход Worker: fetch (webhook /telegram), scheduled (cron), queue (отправка)
  bot.js        # логика: /start, кнопки, расписание, отправка из очереди
  calendar.js   # старый стиль, Пасха, выбор праздника на дату
  message.js    # фраза, вопросы, клавиатуры, слоты
  telegram.js   # вызов Bot API, секрет webhook (выводится из токена)
  data.generated.js  # собирается из data/*.yaml (npm run build), в git не хранится
data/holidays.yaml     # праздник на каждый день
data/questions.yaml    # 14 вопросов с постоянными id
migrations/             # таблица users в D1 (0002 добавила tz и 12 слотов)
scripts/
  build-data.mjs       # YAML -> JS, чтобы Worker не разбирал YAML (лимит 10 мс CPU)
  check-holidays.mjs   # ручная проверка текстов праздников
  preview.mjs          # фразы на N дней вперёд
  deploy.mjs           # всё выкладывание одной командой
test/                  # node:test; D1 подменяется на SQLite (better-sqlite3)
.github/workflows/deploy.yml
```

Таблица `users`: `chat_id`, `slot` (0–11), `tz` (часовой пояс IANA, по умолчанию `Europe/Moscow`), `every` (1–7), `last_sent`, `sent_count` (от него зависит, какой вопрос следующий), `excluded` (JSON со списком выключенных id вопросов).

### Праздники

- `data/holidays.yaml`: 366 дат по старому стилю, около 35 подвижных дней от Пасхи и 16 великих праздников. Источник: azbyka.ru за 2027 и 2028 годы.
- Ключи заданы по старому стилю. Перевод даты идёт через Julian Day Number, Пасха считается по алгоритму Миуса.
- Приоритет: `movable` с `major: true` → `great` → остальные `movable` → `fixed`.
- Поле `end` меняет знак после поздравления (по умолчанию `!`). У Великой пятницы стоит «Сегодня Великая пятница.».

### Вопросы

У каждого пользователя свой случайный порядок вопросов, без повторов внутри круга. Порядок зависит от `chat_id` и номера круга, поэтому хранить нужно только `sent_count`. Выключенные вопросы пропускаются. Если выключить все, бот вернётся к полному списку, но интерфейс выключить последний вопрос и так не даёт. **Не меняй `id`** у существующих вопросов: на них ссылаются настройки пользователей.

## Хостинг и деплой

Хостинг: **Cloudflare Workers Free**. Как завести аккаунт и токены, описано в [docs/cloudflare-setup.md](docs/cloudflare-setup.md).

`deploy.yml` на каждый push и PR запускает тесты и `check-holidays`. На push в `main`, если заданы три секрета, он запускает `npm run deploy`, а `scripts/deploy.mjs` делает остальное:
1. создаёт базу D1 `<имя репозитория>`, если её ещё нет;
2. создаёт очередь `<имя>-send`, если её ещё нет;
3. генерирует `wrangler.jsonc` с id базы (в git его нет);
4. применяет миграции;
5. выкладывает Worker и берёт его адрес на `workers.dev`;
6. кладёт токен бота в секреты Worker;
7. регистрирует webhook (`/telegram`, секрет выводится из токена через SHA-256) и удаляет старые команды из меню.

Скрипт можно запускать сколько угодно раз: он создаёт только то, чего не хватает. Если секретов нет, деплой пропускается с предупреждением. Это удобно для свежей копии шаблона.

Секреты репозитория: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `TELEGRAM_BOT_TOKEN`. Пользователь вписывает их сам, Claude токены не вводит.

### Лимиты бесплатного тарифа, которые учтены

| Лимит | Как учтён |
|---|---|
| 50 внешних запросов за запуск | Отправка идёт через очередь, пачками по 40 |
| 50 запросов к D1 за запуск | Cron читает подписчиков одним запросом и отмечает всех одним `UPDATE ... json_each`, не больше 500 человек за запуск |
| 10 мс CPU | Данные собираются в JS заранее; ожидание сети в лимит не входит |
| 5 cron на аккаунт | У этого бота один cron (288 запусков в день, в лимит запросов укладывается с запасом) |
| 10 баз D1 на аккаунт | Одна база на бота |
| Очереди: 10 000 операций в день | Около 3 300 сообщений в день на весь аккаунт |

Если упрёмся в лимиты, Workers Paid за $5 в месяц снимет почти все из них.

## Как сделать ещё одного бота по этому образцу

1. Скопировать репозиторий: сделать его шаблоном на GitHub (Settings → Template repository) или просто скопировать файлы.
2. Создать нового бота в @BotFather.
3. Добавить три секрета. Cloudflare-токен и Account ID те же, Telegram-токен новый.
4. Push в `main`. Имя Worker, базы и очереди берётся из имени репозитория.

Ботам без рассылки (например, QR) cron и очередь не нужны: убрать их из `scripts/deploy.mjs`.
